# WindowsAppSDK 개선 검토 및 실행 — 2026-09-25

기준: `a1438754`와 이번 작업 트리. Linux Qt의 [보관된 work3 검토](../../../history/26-09-24/linux-qt-improvements-summary.md)와 같은 안정성·입력·포커스·접근성·배포 관점에서 검토했다. Windows의 기존 Graphite/Vulkan/D3D12/DXGI 경로와 native ABI를 유지한다. 당시 `work2.md`, `work3.md`는 변경하지 않았다.

## 적용한 개선

| 영역 | 확인한 문제 | 적용 |
| --- | --- | --- |
| 물리 키 | 영문·숫자·문장부호를 virtual key로 매핑하여 레이아웃이 바뀌면 물리 위치도 바뀐다. NumLock 해제 시 keypad가 navigation 키와 합쳐진다. | native에서 이미 전달하는 scan code와 extended bit를 우선 사용한다. scan code가 없는 합성 입력은 별도 fallback을 쓰며 unknown key끼리 충돌하지 않는다. F13–F24도 포함한다. |
| 논리 키·수명 | printable numpad가 일반 숫자/문자로 바뀐다. repeat가 최초 logical key를 덮어쓰고 포커스 상실 시 눌린 키가 남는다. | numpad의 전용 identity를 유지하고 최초 down의 logical key를 repeat/up까지 보존한다. focus-loss callback에서 남은 키를 한 번씩 synthesized up으로 전달하고 input sequence를 갱신한다. |
| 문자 조회 | `ToUnicodeEx(..., 0, ...)`가 `TranslateMessage`와 함께 kernel keyboard state를 변경할 수 있다. | 조회 호출에 bit 2 (`4`)를 지정한다. 실제 dead-key/IME 실입력 검증은 남아 있다. |
| PlatformView UI 큐 | enqueue 뒤에 `PostMessageW`가 실패하면 실패로 보고한 작업이 큐에 남는다. owner-thread `InvokeAsync`는 Dispose 이후에도 실행된다. 작업마다 native 알림을 보낸다. | 동일 lock 안에서 알림 성공 후 작업을 수락한다. pending 알림을 병합하고 drain 완료 시 재등록 가능하게 한다. 콜백 예외 뒤에도 후속 작업을 처리하고 owner 호출의 disposed 검사도 추가한다. |
| 기존 검증 유지보수 | WinUI 재마운트 검사가 6개 탭 기준 x=540을 클릭한다. 현재 7개 탭에서는 WebView를 연다. | 현재 client 폭과 7개 destination의 index 4 중앙으로 클릭을 계산한다. 첫 실패 결과는 로컬 산출물에 보존한다. |

제품 코드: [키 매핑](../../src/Doroti.Host.WindowsAppSdk/WindowsKeyMap.cs), [키 상태](../../src/Doroti.Host.WindowsAppSdk/WindowsKeyboardState.cs), [입력 host](../../src/Doroti.Host.WindowsAppSdk/WindowsManagedProductHost.cs), [UI dispatcher](../../src/Doroti.Host.WindowsAppSdk/WindowsPlatformViewDispatcher.cs), [native 입력](../../src/Doroti.Host.WindowsAppSdk.Native/src/exports.cpp).

Windows 메시지의 scan code/extended bit와 문자 조회 부작용은 Microsoft의 [Keyboard Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input), [ToUnicodeEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-tounicodeex) 계약을 기준으로 했다. 알림 실패는 [PostMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)의 반환값을 따른다.

## 검토했으나 별도 후속 작업으로 남기는 항목

전체 플랫폼 품질 상태는 **PARTIAL**이다. 아래 소스 검토를 이번 기능·성능 승인으로 해석하지 않는다.

| 우선순위 | 항목 | 현재 근거와 다음 완료 기준 |
| --- | --- | --- |
| P1 | HWND 포커스 요청 및 Tab 순환 | `RequestFocus`는 실제 HWND 요청 없이 관측 이벤트를 생성한다. native sibling으로의 `WM_KILLFOCUS`도 별도로 억제한다. 요청/관측 분리, UI owner dispatch, native/framework 간 키 소유권, 정·역방향 Tab을 함께 설계하고 실제 HWND 상태로 검증해야 한다. 이번 focus-loss 수정은 전달받은 callback에 적용되며 전체 순환 해결은 아니다. |
| P1 | 접근성 텍스트 | UIA의 value/selection/state 변경 알림은 이미 있으나 `ITextProvider`/`ITextRangeProvider` 구현은 확인되지 않았다. caret·선택 범위·문자 위치 및 Narrator/NVDA의 실제 탐색을 검증할 필요가 있다. |
| P1 | GPU 장애·종료 | Windows에는 device-lost와 idle 미확인 구분, 리소스 quarantine, presentation retirement 보호가 이미 있다. Qt의 dispose 보완을 그대로 중복 적용하지 않았다. 실제 GPU 장애/timeout 주입과 terminal 횟수·반복 종료 검증은 이번에 재실행하지 않았다. |
| P1 | resize·DPI | 기존 resize generation과 prepared frame 검사가 있다. 실제 OS resize 표시 프레임, 다중 모니터/DPI, minimize/restore 검증은 이번 입력 회귀와 별개다. geometry continuity는 `notVerified`. |
| P1 | touch/pen·capture | native mouse cancel/capture-loss와 managed pointer adapter가 있다. mixed native/framework 드래그·touch/pen 실기기 소유권 검증은 `notVerified`. |
| P1 | 배포 | native hash/provenance와 self-contained runtime 확인 경로가 있다. 저장소 밖 package-only 소비자 및 깨끗한 Windows VM 실행은 이번에 수행하지 않았다. |
| P2 | 성능·진단 | UI 알림 병합은 메시지 수를 줄이지만 CPU·입력 지연 전후 측정은 `notMeasured`. GPU fence/queue 대기 제거와 렌더링 구조 변경은 측정 없이 적용하지 않는다. ABI version/size 검사를 유지했다. |

물리 키보드 레이아웃 전환, 한글 IME, dead-key 실제 조합, Narrator/NVDA, 실기기 touch/pen 및 OS 메시지 큐 고갈 주입은 `notVerified`다.
