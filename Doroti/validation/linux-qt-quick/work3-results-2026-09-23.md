## Measurements and acceptance boundaries

[Before](results-2026-09-23/workloads-before.json) and [after](results-2026-09-23/workloads-after-idle.json) use the same Debug configuration, Wayland, 720×640, DPR 1 and llvmpipe VM. After runs cover the affected idle cases only. Image captures remain 720×640; mean absolute RGB-channel difference from before is below 0.07/255. The samples are observations, not a negotiated performance budget.

| Idle workload | CPU before → after | `frameSwapped` intervals before → after | Peak observable process-tree PSS before → after |
| --- | --- | --- | --- |
| 0 WebViews | 51.49% → 1.12% | 299 → 0 | 184.8 → 193.2 MB |
| 4 WebViews | 76.35% → 0.47% | 280 → 0 | 402.2 → 408.6 MB |

The after interval percentiles are **null** because no intervals were sampled. The PSS increase in these short VM samples is not a memory regression conclusion. A first 0-view after attempt showed a black window; it is retained in `/tmp/doroti-qt-work3-workloads-after`. A stale startup metrics generation was found (`scene=4`, `current=6/7`); scheduling a replacement scene restored the window. The corrected after capture and a separate repeat show the same visible content as before. Active workload intervals and CPU/GPU timings remain in the before result; `frameSwapped` is not physical scanout or input latency.

## Reproduction

Run from the repository root with fresh output directories:

```sh
python3 Doroti/validation/run-with-timeout.py dotnet build DorotiTestbedApp/linux/DorotiTestbedApp.Linux.csproj
python3 Doroti/validation/run-with-timeout.py python3 Doroti/validation/linux-qt-quick/run-suite.py \
  --output <new-directory> --shim <matching-app-dir>/libdoroti_qt_host.so \
  --app <matching-app-dir>/DorotiTestbedApp.Linux.dll --qpa wayland --product
python3 Doroti/validation/run-with-timeout.py python3 Doroti/validation/linux-qt-quick/verify-lifecycle.py \
  --output <new-directory> --app <matching-app-dir>/DorotiTestbedApp.Linux.dll \
  --driver <matching-driver-dir>/libproduct-driver.so --qpa xcb
python3 Doroti/validation/run-with-timeout.py python3 Doroti/validation/linux-qt-quick/verify-package-consumer.py \
  --output <new-directory-outside-checkout> --quick --webengine --qpa wayland
python3 Doroti/validation/run-with-timeout.py cmake -S Doroti/validation/linux-qt-quick/wsi -B <wsi-build>
python3 Doroti/validation/run-with-timeout.py cmake --build <wsi-build> -j2
# With the validation layer enabled and loadable:
QT_QPA_PLATFORM=xcb DOROTI_QT_WSI_SYNC_DELAY_MS=50 VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation \
  python3 Doroti/validation/run-with-timeout.py <wsi-build>/qt-wsi-resize
```

The package runner packs the current built source outputs; build the intended configuration first. Driver and app shim must come from the same build. Displayless CI checks the native copies and managed contracts only. Physical hardware, screen-reader and clean-machine approval require those environments and separate recorded results.
