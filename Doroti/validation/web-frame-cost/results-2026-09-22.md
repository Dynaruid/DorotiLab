# Web 일반 화면 비용 — 2026-09-22

**PARTIAL. 전체 work.md 완료 또는 성능 PASS가 아니다.** 일반 화면에서 원인을
좁힐 계측·재현 driver를 구현하고 Release 실측과 후보 3쌍 비교를 수행했다.
텍스트 후보는 채택 기준에 미달하여 원복했다. 진단 OFF에서 불필요한 raster
interop/message를 차단한 수정과 계측을 남겼다. 버벅임 해결을 주장하지 않는다.

## 변경과 범위

- bootstrap에서 `dorotiAllocationProfile=1`을 `DOROTI_ALLOCATION_PROFILE`로
  전달한다. stage/layout/allocation 실제 설정은 owner에서 export한다.
- `dorotiFrameCost=1`은 Worker의 고정 크기 숫자 ring을 활성화한다. 입력 수신,
  동기 Framework callback, raster/submit을 기록하며 16,384개 초과는 덮어쓰기
  개수를 보고한다. OFF에서는 ring을 만들지 않는다.
- 기존 MessagePort의 명시적 진단 요청으로 export한다. 최종 `finish`는 같은
  Worker turn에서 managed allocation endpoint와 ring을 함께 읽는다. 프레임
  중 JSON/배열 export를 하지 않는다. 이전 export 후 할당 기준점을 설정한다.
- `CaptureCostDiagnostics`는 전체 stage/work trace JSON을 반복 생성하지 않는다.
  profile 집계, scroll endpoint, cache, heap/GC 정보를 제한된 형태로 보낸다.
  renderer의 picture/paint/path/text 변환에는 상세 계측 ON에서만 self-time scope를 추가했다.
- `BrowserHostAdapter.RecordRaster`와 paint duration 측정을 bootstrap의
  `DOROTI_WEB_DIRECT_TRACE`로 제한했다. Worker에서도 OFF이면 진단 message
  payload를 만들지 않는다. 그리기·입력·semantics 처리는 유지한다.
- 명령 저장·snapshot 수명·캐시 한도·dirty/layout/inherited/GlobalKey 계약,
  앱 animation·DPR·runtime 기본값은 바꾸지 않았다. Flutter 생성 Framework
  파일과 converter를 수정하지 않았으므로 재생성 fixture 대상은 없다.

## 최종 산출물 관측

`final-atomic-minimal`은 텍스트 후보를 원복하고 진단 OFF 전송을 차단한 최종
자산이다. 한 번의 회귀 관측이며, 최종 수정의 3쌍 성능 채택 증거가 아니다.

| 구간 | Framework p95 | raster/submit p95 | 동기 owner 구간 합계 | Framework frame 수 |
| --- | ---: | ---: | ---: | ---: |
| S1 첫 방문 | 23.32ms | 11.76ms | 829.2ms | 78 |
| S2 반복 왕복 | 4.80ms | 6.48ms | 1234.2ms | 205 |

Framework와 raster의 p95를 단순 합산해 전체 frame p95로 부르지 않는다.
owner 합계는 입력/Framework/raster 동기 구간의 합집합으로, 전체 owner thread
CPU 또는 GPU 시간은 아니다. S3 새 scene 제출 간격 p95 15.23ms,
최대 62.78ms, 50ms 초과 1회. 물리 표시 FPS가 아니다.

S3 owner 할당은 약 193.8KB/frame, managed heap estimate 29,293,440 B,
WASM capacity 208,404,480 B였다. GC collection delta는 [37,1,1]이며 pause
시간은 모른다. 반복 방문 후 전체 retained State/GPU memory 수렴은 검증하지 않았다.

입력 지표는 dispatch watermark 이후의 첫 new-scene submit을 찾는 **proxy**다.
경계에서 화면을 바꾸지 않은 wheel도 다음 submit과 연결될 수 있다. 따라서
실제 input을 반영한 scene의 p95나 물리 latency로 사용하지 않는다.

최종 자산의 최소 계측/OFF 한 쌍에서는 S3 renderer process CPU가
11,163.6/10,992.1ms로 약 1.6% 차이였다. 이는 계측 비용의 탐색적 대조이며
반복 측정·owner 전용 CPU가 아니므로 “계측 비용 0” 또는 통계적 확정은 아니다.
