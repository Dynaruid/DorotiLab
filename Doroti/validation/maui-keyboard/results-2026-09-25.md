# MAUI Windows / Android 입력 개선 — 2026-09-25

WindowsAppSDK 개선에 이어 두 MAUI host의 실제 입력 경로를 검토하고 수정했다.
**입력 계약·빌드·Galaxy 입력 회귀는 PASS. Windows 입력 회귀도 통과하지만 프로세스 종료 gate가 실패하여 전체 상태는 PARTIAL이다.**

## 적용

- Windows DXGI surface가 모든 키에 `0x100000000 | VK`를 사용하던 경로를 USB HID physical / Flutter logical key로 교체했다. SKGLView 경로도 같은 변환을 쓴다. WindowsAppSDK의 변환 구현은 `Doroti.Hosting.WindowsKeyboardMap`으로 옮겨 공유한다. scan-code-zero의 좌우 modifier fallback도 보존한다.
- MAUI의 pressed state는 최초 logical identity를 repeat/up까지 유지한다. 반복 down, 포커스 재획득 후 첫 repeat, blur 뒤 늦은 native up을 일관되게 처리한다. 키보드 시간은 UTC ticks 대신 `DorotiFrameClock.Now`를 사용한다.
- Windows에서 modifier/keypad 구분, `WasKeyDown`, non-mutating `ToUnicodeEx`를 적용했다. 실제 창 비활성화와 입력 소유자 detach에서 남은 키를 해제한다. XAML `LostFocus` 중 이미 같은 owner/하위 요소가 다시 포커스를 가진 경우에는 키를 취소하지 않는다. 이 조건은 실행 중 반복 키가 잘못 해제되는 현상으로 확인했다.
- Android는 알려진 evdev scan position과 scan-code-zero keycode fallback을 구분한다. logical key는 Android keycode/문자를 따르며 numpad·문장부호·F1–F12 fallback을 보강했다. device별 비표준 scan code의 완전한 호환은 승인하지 않는다.
- Android view/window blur, handler 재연결, dispose에서 키를 정리한다. 합쳐진 `ViewTreeObserver`에서도 동일 listener를 해제한다. `ACTION_MULTIPLE`은 가짜 down으로 만들지 않고 전달한다. Unicode scalar를 검증하여 dead-key flag, surrogate 및 범위 초과 값이 문자로 들어가지 않게 한다.
- 활성 EditText/TextBox의 native 텍스트·IME 편집 소유권은 유지했다. Android의 기존 텍스트 변경/selection 동기화 정책은 바꾸지 않았다.
- WindowsAppSDK의 수동 `PostMessageW` 큐와 달리 MAUI는 기존 dispatcher를 사용한다. Windows resize queue의 claim/cancel·종료 순서는 변경하지 않았다.

Windows 오른쪽 Shift 주입은 원본 Win32 메시지부터 왼쪽으로 변환되어 관측됐다. 사용자가 기존 **PowerToys remap 설정**을 확인했다. 해당 설정을 변경하지 않았고, 불필요한 native message hook도 남기지 않았다. 양쪽 modifier 동시 입력·한쪽 해제는 managed 계약으로 검증했고, Windows live blur는 왼쪽 Shift로 확인했다.

제품 경로를 관측하는 `keyboard-input` Testbed 모드를 추가했다. 명시적으로 선택한 검증 화면에서만 framework key/text 이벤트를 기록한다. Android 로그는 테스트 앱 PID로 한정하고 검증 후 앱을 종료했다. 물리 키보드, 사람이 입력한 한글/IME·dead-key 합성, 다양한 Android 입력 장치는 `notVerified`다.

## 남은 Windows 종료 실패

텍스트 입력 후 창을 닫으면 native 창은 닫히지만 프로세스가 20초 안에 끝나지 않는다. 입력 검사 자체의 실패와 구분한다. 렌더/metrics worker 정리와 `Window.Closed`/`Application.Exit` 호출 이후에도 WinUI native message loop가 남는 것을 임시 계측과 `dotnet-stack`으로 확인했다. 강제 종료를 정상 종료 PASS로 처리하지 않았다.

`HEAD:a1438754`의 **DorotiWindowsDxgiSurface.cs만** 별도 MSBuild Compile 입력으로 지정한 비교 빌드에서도, 같은 새 검증 화면의 텍스트 입력 후 종료가 20초를 초과했다. 전체 저장소를 이전 버전으로 되돌린 비교는 아니다. 포커스를 입력창 밖으로 옮긴 후에도 재현됐다. 종료 변경을 추측으로 남기지 않고 기존 close 구현을 복원했다. 최종 출력은 현재 수정된 surface로 다시 빌드했다.

이 실패는 별도 원인 조사와 종료 회귀가 필요하다. 기존 GPU 자원 정리 보호를 우회하거나 `Environment.Exit(0)`로 감추지 않았다. 기존 Windows resize visual-continuity의 PARTIAL 상태도 이번 입력 작업으로 바뀌지 않는다.

원시 이벤트/로그/화면/stack은 삭제 가능한 `Doroti/artifacts/validation/maui-keyboard/`에 있다. 보존 요약: [Galaxy 결과](android-result-2026-09-25.json), [Windows 결과](windows-result-2026-09-25.json).
