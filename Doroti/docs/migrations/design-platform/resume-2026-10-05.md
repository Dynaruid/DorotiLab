기준은 당시 work2 계획([구조·작업 보관 요약](../../../../history/26-10-05/work2-summary.md)), [이전 인계 기록](session-handoff-2026-10-05.md), 현재 실제 소스다. 이전 16개 완료 항목과 실행 당시의 PASS를 최신 전체 수락으로 확대하지 않는다. 기존 큰 미커밋 작업 트리를 보존하고 컴파일러 `tools/Doroti.DartToCSharp`는 수정하지 않았다.

## 이번에 수정한 결함

- Cupertino Overlay 대화상자가 호출 위치의 CupertinoTheme를 잃었다. Native/Overlay 양쪽에 captured theme와 localization을 연결했다.
- native content 생성 결과가 invocation의 늦은 취소 거절에서 누출될 수 있었다. 생성 delegate 안에서 소유 결과를 먼저 기록하고 실패/닫기/취소 시 창과 registry를 정리한다. returned handle의 중복 Dispose는 같은 retirement 작업을 기다린다.
- RawTooltip의 비동기 생성 뒤 unmounted context 접근과 late install 누출을 제거했다. owner를 먼저 capture하고 install 성공 이전의 handle은 finally에서 정리한다. Material의 위치 delegate도 native anchor 계산에 사용한다.
- Windows 추가 창이 HWND 연결 전에 등록될 수 있었다. native attachment receipt를 기다려 생성과 부분 종료를 직렬화한다.
- 자동 Show 실패/취소가 `OnCreated`의 실제 종료보다 먼저 startup receipt를 완료했다. 두 작업의 실제 완료를 기다리며, self-close의 정상 Show 취소는 오류로 승격하지 않는다. MAUI 최종 종료는 closed-window startup receipt도 기다린다.
- MAUI public 등록은 descriptor factory 또는 startup 타입을 받아 process 준비 이후 생성한다. 이미 생성된 descriptor를 받는 설정은 provider 내부 경로로 제한한다.
- Windows popup 메뉴가 구현하지 않은 shortcut/role을 지원으로 평가하고 separator를 명령으로 만들었다. 미지원 사전 평가와 실제 separator를 연결했다.
- 첫 NuGet restore에서 아직 resolved provider가 없는데 Desktop capability를 검사했다. desktop companion의 restore graph는 명시 선언으로 만들고 provider 기능 거절은 resolved build 단계에서 수행한다.
- provider/Target의 resolved package version·core range·protocol·runner metadata를 대조한다. Target은 계획의 `doroti.target-package/v2`와 명시 packageVersion을 사용한다.
- release 도구는 workspace alias/provider/project metadata로 roots를 찾고 core/design/provider 버전을 독립 인자로 받는다. receipt에는 실제 nuspec·native 자산 hash·지원 manifest·소스 hash와 alias별 runtime 범위를 남긴다.
- doctor를 typed CLI 계약으로 이행하면서 runner CWD/global.json·SDK feature band/prerelease·scope·timeout→PARTIAL을 유지했다.
- 검증 파일이 없는 fixture가 상위 실제 저장소를 찾아 검증을 재귀 실행했다. 가장 가까운 저장소 경계를 고정하고 누락 시 명시 실패한다. 해당 테스트 소유 프로세스들을 종료했으며, fixture 자체에도 bounded process-tree wrapper를 적용했다.
- Material Raw 메뉴 검사에서 지속적인 frame 예약을 발견했다. 로컬 Flutter `layout_builder.dart`와 대조해 누락된 `_needsBuild`/`_previousLayoutInfo` 완료 기록을 복구하고 Overlay layout 정보의 값 비교를 구현했다. 메뉴 열기·항목 선택·닫기와 radio 선택 회귀가 통과했다.

## 검증 경계

실제 결과는 [최신 재개 검증 receipt](resume-verification-2026-10-05.json), [execution.json](execution.json) 및 각 verification JSON에 기록한다. 테스트는 1,200초 외부 timeout을 사용한다. 실패한 후보와 raw run은 조사 증거이며 PASS로 집계하지 않는다.

현재 Windows에서 실행한 native 창·Visible 상태·GPU/native drain 검사는 물리 키보드/IME, 화면 scanout, mixed-monitor DPI, screen reader, clean-machine 설치·서명 수락이 아니다. Apple native/device, Linux Qt display, matching Android/iOS 장비·trim/AOT는 가용 환경에서 별도로 검증해야 한다.

전체 체크박스를 일괄 완료하지 않는다. Cupertino context menu/native restoration·focus/Semantics 전환, Qt/AppKit 메뉴·창 역할 확장, mobile development transport와 모든 플랫폼 제품 수락은 실제 구현·검증 범위대로 남긴다.

## 추가 구현과 최신 검증

- 마지막 native view 제거 뒤 binding teardown의 frame 예약을 막고, Windows lifecycle 폐기 전에 공유 tree branch를 해제한다. 중복 Detach는 폐기된 invocation scope에 들어가지 않는다.
- Qt의 개별 창 닫기에서 공유 Session.Shutdown을 제거했다. worker continuation이 Qt native focus API를 다른 thread에서 호출하지 않도록 GUI owner queue도 연결한다. strict smoke는 관리 framework exception까지 거절한다.
- font invalidation은 typed application event로 바꾸고, Web provider의 개발 receipt 연결은 명시적인 public host 계약을 사용한다. Web declarations는 Target/provider만 포장하며 buildTransitive props가 native JS link 설정을 유지한다.
- 열린 RawTooltip 목록은 application별로 소유한다. Auto Overlay·dismiss·pending-show unmount를 검사하고, ExpansionTile controller listener가 자신의 view scope를 사용하도록 수정했다. ClipboardStatus는 닫힌 owner/disposed notifier의 취소를 framework 오류로 보고하지 않는다.
- Android tooling은 실제 ADB를 bounded probe하여 허가된 장치·RID/ABI를 필터링한다. 명시 선택/단일 장치 선택/복수 장치 거절·잘못된 serial 거절은 fixture process로 검증했고 실제 CLI의 현재 연결 목록은 비어 있다. 장치 배포·mobile 개발 transport 수락은 아니다.
- doctor는 Partial=exit 2, Fail=exit 1을 유지하고 all에서 독립 profile을 계속 검사한다. 구 PowerShell doctor 구현은 typed CLI 전달로 정리했다. 샘플의 Windows MAUI는 `windows-maui`라는 명시 alias로 선택한다.

검증 결과와 package별 버전·hash는 durable JSON에 기록한다. Windows 독립 후보는 core alpha.2 / Material alpha.3 / Cupertino alpha.2 / Windows provider alpha.4 조합으로 새 NuGet restore·publish·native 두 창 실행이 통과했다. Web 독립 후보는 core alpha.2 / Cupertino alpha.2 / Web provider alpha.4 조합으로 Offline publish와 Chrome first frame/focus/외부 요청 0건이 통과했다. signing/clean-machine/physical 수락은 notVerified다.

최신 WindowsSmoke 집계와 Windows MAUI Graphite integration은 PASS다. Developer와 전체 Release 집계가 이번 재개 중 PASS했다. 이후 설치 provider metadata 부정 fixture와 Qt profile fixture도 각각 PASS다. 초기 Qt run의 focus thread 오류는 전체 PASS에서 제외했다. GUI owner 수정 후 Qt two-window/desktop/input/resize의 엄격한 재실행과 build/template/typed development/native-copy profile fixture가 PASS했다. Qt 수락은 WSLg Wayland와 software Vulkan 범위다.

## 계속 필요한 구현

1. Cupertino native context-menu preview와 공통 route restoration/focus/Semantics 조정, 실제 RawTooltip hover/long-press 및 늦은 설치 수락.
2. Qt/AppKit의 추가 WindowKind·OS menu, 모든 provider의 완전한 staged coordinator/typed 서비스 종료 계약과 sample/native bootstrap 중복 제거.
3. Built-in mobile development/device transport·template/native-maintenance 서비스와 IDE 실제 Run/Reload/Restart/Stop 수락.
4. G1 slow-consumer·reentrant modal/close·recreation·late IME isolation 및 전체 API/소유권 semantic audit.
5. Apple/연결 Android/iOS 장치·trim/AOT·서명·clean-machine·물리 IME/접근성/mixed-DPI 수락. 현재 없는 환경은 별도 SKIPPED/notVerified다.

DS4 다섯 항목은 확인된 descriptor/resource·공급 문서·locale 계약 범위대로 완료했다. 다른 단계와 최종 수락 체크리스트의 미완료를 지우지 않았다.

전체 계획은 계속 inProgress다. 현재 알려진 실행 실패는 해결했지만 위 미구현 API·플랫폼·물리 수락 때문에 wholePlanComplete는 false로 유지한다.
