# F0 typed Flutter framework compiler

F0 introduces a product-facing compiler track that is separate from the historical C0-C5 fixture levels. The `framework-semantic` / `flutter-framework-f0` profile requires Migration IR 3.0 and resolved analyzer output. The initial always-buildable Flutter closure is `package:flutter/src/foundation/object.dart` plus `dart:core`; its immutable revision, declarations, and direct dependencies are pinned in `migration/flutter-framework/f0-closure.json`. The selected-source hash remains provenance metadata, not an equality acceptance gate.

The Dart helper emits `doroti.dart-analyzer-output/v3`: a resolved library/fragment/import graph, canonical element identities, declaration/member metadata, types, and a recursively typed AST. `MigrationLoweringPipeline.LowerTyped` accepts only the typed IR. `SemanticCSharpEmitter` accepts only lowered semantic declarations and has no raw Dart source or regular-expression parser input. C0-C5 retain their source-slice emitter strictly behind `FixtureHistoryLoweringPipeline` so their old behavior fixtures remain reproducible without being presented as framework coverage.

Every F0 run writes `doroti.framework-coverage/v1`. A successful run has status `mechanical-generated`: it proves candidate generation, not review, promotion, behavior, or milestone completion. The gate fails on a declaration omitted from the selected library, syntax-only analysis, an AST semantic without a lowering visitor, analyzer errors, or generated C# syntax/compile errors. Diagnostics carry the source span, canonical element id, dependency path, support state, and required action. Runtime/native boundaries are assigned by `migration/flutter-framework/f0-semantics.json`; they cannot become silent no-op implementations.

The compiler identity pins Dart SDK, analyzer 9.0.0, Flutter revision, Migration IR 3.0, `framework-f0.0-typed` rules, `csharp-net10.f0-typed-visitor`, runtime binding version, and workspace id. G3-0 regenerates the candidate from current source and compares it with the committed candidate. Pre-Goal3 build/runtime PASS strings are not copied into the new evidence.

The profile establishes one real mechanical framework candidate. G3-2 records the byte-identical F0/G3-1 alias, reviews `objectRuntimeType`, promotes it to `src/Doroti.Flutter.Framework.Foundation/object.cs`, and validates product compile/API/behavior and deterministic re-promotion. `f0-evidence.json` therefore records one reviewed generated declaration and `milestoneComplete: true`. It does not claim F1-F4 framework breadth.
