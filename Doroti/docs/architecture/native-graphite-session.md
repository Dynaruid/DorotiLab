# Native Graphite session ownership

Status: **NG2 PARTIAL**. `SkiaGraphiteSession` implements Metal and Vulkan recording and GPU-resource boundaries. Vulkan uses the pinned native ABI 3 (enabled descriptors, persistent texture state, binary semaphores and external device-loss notification). Graphite is now the user-selected default in Windows App SDK, Windows MAUI, Android, Qt, AppKit, iOS and Mac Catalyst. See [default adoption and validation boundaries](../validation/native-graphite-defaults-2026-09-09.md); Linux and Apple product execution was skipped by the user. This configuration decision does not establish all NG2/NG7 qualification gates.

Each session represents one context generation and one owner thread. It owns a 256 MiB context budget, a 64 MiB recorder budget, one recorder, one image-provider cache and at most three outstanding frames. A second view gets a separate session and cache, even when it shares a platform device or queue. `SkiaGpuSurfaces.Register` lets existing renderer offscreen captures use that recorder. Runtime effects identify this path as `skiasharp-graphite-metal-gpu` and retain the renderer's existing per-owner/per-generation cache keys.

The host owns and retains the device, queue and drawable texture. `BeginMetalFrame` creates an external texture wrapper and a registered surface; only one frame may be actively recorded at a time. `CancelRecording` discards an unsubmitted frame. `Submit` snaps, inserts and submits asynchronously. Neither operation reports a frame as presented.

After submission, the host puts its presentation command buffer on the **same Metal queue**. A command-buffer completion is marshalled back to the session owner thread before `CompleteGpuWork` disposes the surface, backend wrapper and recording. The host separately checks surface generation and records the presentation terminal. The AppKit candidate preserves its transaction-presentation path during live layout. Committed callbacks retain their drawable until GPU completion; the next frame is requested after bounded-queue backpressure clears.

Readbacks are optional capture/diagnostic requests. `RequestReadback` must precede `Submit`; the native callback copies bytes into a managed result without throwing across the native boundary. A frame cannot be returned while its callback is pending, and readback pixels never feed presentation. The window probe has zero CPU readbacks/full-frame copies; the separate texture contract uses readback solely for pixel assertions.

Shutdown stops admission, waits for host completion callbacks, releases renderer-owned GPU caches, then releases the session's image cache, recorder and context before the platform queue/device. `Dispose` rejects outstanding frames and pending readbacks rather than waiting indefinitely or freeing live work. Failed submission faults the session; recovery must first establish a host GPU terminal, then create a new generation. There is no automatic Ganesh fallback. Device-loss teardown, a missing completion marker, reattaching a previously disposed native view and an unavailable owner dispatcher remain qualification gates; the current product candidate must not be described as passing them.

The shared session does not change Framework build/layout admission, exact viewport descriptors, or the Web worker's existing Graphite/Dawn and explicit WebGL implementations. The AppKit candidate keeps picture raster caching disabled while that separate cache policy is qualified. Its handler-release event invalidates renderer caches before the session is destroyed.

## Vulkan ownership

`CreateVulkan` takes the exact enabled feature structures/extension names and a rooted procedure callback. It never infers enabled features from supported-feature queries. `VulkanTarget` wraps a host image once and remains live across frames; `BeginVulkanFrame` rejects a busy target, foreign generation, concurrent recording or the frame limit. `GetState` reads scheduled layout/queue ownership for the external barrier. Only after the copy fence and `CompleteGpuWork` may the host call `SetStateAfterGpuCompletion` with the actual return transition. Target disposal rejects a live frame. `SubmitVulkan` accepts borrowed binary semaphores; the host owns their GPU/platform consumption.

The host also supplies `ResolveNativeSymbol` for the same live module used by SkiaSharp. The shared assembly contains no static imports of Doroti's native Vulkan extensions: they use explicitly resolved C ABI function pointers, and browser session creation rejects immediately. This avoids adding unavailable Vulkan extension symbols to WebAssembly's static link. The first Web build exposed that boundary and its linker failure remains in the execution evidence.

The Windows candidate records into the persistent retained backing, checks latest viewport/input admission before submission, copies on the same graphics queue using the queried layout and explicit barriers, completes the copy fence, and returns the frame. The existing native Composition slot availability/receipt ledger independently governs display and slot retirement. No CPU readback feeds product presentation. Picture raster caching is disabled for this candidate while its separate policy is qualified.

`NotifyVulkanDeviceLost` forwards an observed `VK_ERROR_DEVICE_LOST` into the pinned Skia `VulkanSharedContext`; it permanently closes admission. It is not an abandon operation for a timeout or an unknown live-GPU state. Windows retains the whole renderer/presenter state if shutdown cannot establish safe GPU ownership. The native host joins its raster thread before `Run` returns. After that join and a successful device drain (or observed device loss), `TakeVulkanShutdownOwnershipAfterGpuDrain` permits a terminal-only handoff to the closing thread. No rendering can resume in that generation. This closes the actual host shutdown-thread mismatch without relaxing ordinary owner-thread checks.

The fixture exercises both GPUs through opaque/Acrylic output, reset and simulated device-loss recovery. NVIDIA's historical 50 ms receipt failures were confirmed as delayed matching statistics (about 249 ms Ganesh / 253 ms Graphite). The user accepted this latency: NVIDIA now has a 1,000 ms budget; other vendors retain 50 ms. The same present id/tag/nonempty display-instance receipt is required. PreparedReceiptsOver50Milliseconds preserves late-response diagnostics, and missing receipts still fail. Ordinary output uses DwmFlush (native mode 1); strict prepared frames use display statistics (mode 2). Android's native ABI 3 probe is separate from the managed session and MAUI/Surface presentation. Linux and Apple product execution in this follow-up was explicitly skipped by the user.

Reproduce the Metal contract and Ganesh/Graphite window probes with:

```sh
python3 Doroti/validation/appkit-metal-spike/run-graphite.py
```

The runner builds once, launches the actual app executable to capture Metal validation output, and gives every build/test child process an external 1,200-second timeout. Its PASS applies only to the selected probe contracts. Product default promotion, device loss, physical display/input/accessibility acceptance, performance, and cross-platform deployment require separate evidence.

## Platform output adapters (default adoption)

`Doroti.Skia.Vulkan` is a native-host-only assembly, separate from the shared renderer and the Web build graph. `GraphiteVulkanWindow` owns one hardware Vulkan 1.1 device/graphics queue and forwards exactly the enabled instance/device extensions and feature bits to the ABI 3 session. Android owns an ANativeWindow reference behind a MAUI SurfaceView handler. Qt owns its QWindow/QVulkanInstance/VkSurfaceKHR, and supplies the actual enabled extension list through the feature-bit-10 extension of its v2 surface descriptor. Managed code owns both swapchains. Qt input, IME, clipboard and accessibility callbacks remain in the same window class.

WSI rendering uses a persistent color image, an acquire fence, Graphite recording, an ordered GPU copy/transition and a copy fence, then a binary-semaphore-waiting queue present. A queue drain makes semaphore reuse safe. Resize, abandoned acquired images and surface destruction retire the old swapchain after draining GPU work. No CPU readback feeds presentation. Queue-present acceptance is recorded separately from physical display completion.

Windows MAUI uses an exact-LUID Vulkan device to import its shared D3D12 backing resource. Explicit EXTERNAL/graphics queue-family transfers and GENERAL/COMMON state are separated by completed Vulkan and D3D12 fences. Existing CompositionDrawingSurface copy/visual-commit ownership remains with the host. A successfully joined raster thread and GPU drain are required before terminal ownership transfer. Superseded viewport completions use the renderer's superseded terminal; actual errors still use failed.

The UIKit Graphite handler owns an MTKView, Metal queue and session; it does not manufacture a GRContext to satisfy the old SKGLView contract. The MAUI logical SKGLView remains the input contract. Drawable texture wrapping, submission, same-queue presentation completion and frame release happen on the UI owner. Its initial implementation drains one frame synchronously, so throughput/latency remains a separate qualification item. AppKit keeps its existing asynchronous completion path.

Android AOT can bind Skia P/Invokes directly. Its host AAR therefore embeds ABI 3 as `libSkiaSharp.so`, and the runner excludes the stock package runtime at the application dependency root. Loading a differently named library through a managed resolver alone is insufficient; that first failure is preserved. Desktop native assets live in `graphite/` with build provenance, SHA-256 and license notices. The runtime validates the desktop ABI/RID/hash before selecting the library.
