# G3-2 framework candidate review and promotion

G3-2 keeps compiler-owned `.g.cs` candidates below `migration/generated-candidates/` and ordinary product `.cs` below `src/`. `Directory.Build.props` excludes candidate roots, every product build rejects an explicitly included non-intermediate `.g.cs`, and architecture validation requires every source in a promotion-managed product directory to have a symbol entry in `migration/promotion.json`.

The `doroti.framework-promotion/v2` manifest records the canonical Dart element and source span, pinned candidate and old-candidate hashes, aliases such as the byte-identical F0 candidate, reviewer/state, issue category, fix owner, validation cases, optional symbol patch, and target path. Supported issue categories are `compiler-general`, `framework-specific`, `runtime-boundary`, and `upstream-ambiguity`. A `compiler-general` issue must be `resolved-in-compiler` and cannot carry a product patch. Only reviewed non-compiler issues with `approved-adaptation` may use a `doroti.framework-symbol-patch/v1` exact replacement.

The standard composition changes the compiler-only `<auto-generated>` marker to `<doroti-reviewed-framework-source>` so promoted files receive normal analyzer coverage. It then applies an approved symbol patch, if present. The result is normalized UTF-8/LF and written atomically only after all old-candidate/current-source/new-candidate comparisons are conflict-free.

Run the four deterministic operations from `Doroti/`:

```powershell
dotnet run --project tools/Doroti.SourceTools -- review --manifest migration/promotion.json --output artifacts/promotion
dotnet run --project tools/Doroti.SourceTools -- diff --manifest migration/promotion.json --output artifacts/promotion
dotnet run --project tools/Doroti.SourceTools -- promote --manifest migration/promotion.json --output artifacts/promotion
dotnet run --project tools/Doroti.SourceTools -- rebase --manifest migration/promotion.json --output artifacts/promotion
```

`review` validates provenance, spans, hashes, owners and patch policy. `diff` reports the three inputs. `promote` updates ordinary `.cs` only when every item is `add`, `clean-update`, or `unchanged`. `rebase` is read-only and reports conflicts. The compiler validation creates clean, incremental, differently rooted mirror promotions and an intentional upstream/local edit conflict; the conflict must leave the current `.cs` byte-for-byte untouched.

The initial reviewed set contains five declarations in three product files: the F0 `objectRuntimeType` candidate and G3-1 `Category`, `DocumentationIcon`, `Summary`, `objectRuntimeType`, and `Tolerance` selection (the shared F0/G3-1 object candidate is one canonical element). `Doroti.Framework.Foundation` and `Doroti.Framework.Physics` compile and package these ordinary sources. The generated and promoted APIs have identical source bodies after the review-marker transform, and the validation executes the same constructor/default/runtime-type/string trace used by the G3-1 generated consumer.

Machine-readable completion evidence is `migration/flutter-framework/g3-2-evidence.json`. This promotion does not claim the unselected F1-F4 inventories; their remaining blockers stay in their v2 evidence until G3-B0 and later milestones review those symbols.
