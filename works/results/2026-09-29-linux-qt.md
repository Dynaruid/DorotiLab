## 환경과 증거

- Ubuntu 26.04, kernel `7.0.0-34-generic`, linux-x64, .NET SDK `10.0.400`, Qt `6.10.2`.
- Wayland 세션 및 그 안의 xcb/XWayland. DPR 1. VMware SVGA II VM.
- Quick: Graphite/Vulkan, Qt basic GUI/render loop, **softwareVulkan=true**. 물리 GPU 결과가 아니다.
- Widgets 비교: Ganesh/OpenGL, VMware SVGA3D, Mesa `26.0.8-1ubuntu0.3`.
- Debug/JIT native 자동 실행, Qt 렌더 surface 캡처, 합성 native 이벤트 및 CPU offscreen을 구분했다.
  Quick `grabWindow`는 실제 렌더 surface 캡처이며 물리 모니터 scanout 검증이 아니다.
- 최종 CLI aggregate `LinuxSmoke` 및 `Source` PASS; sample/template native 소스 일치와 후보 hash 재검사 PASS.
- 모든 실행은 1,200초 한도. resize는 환경별 20회이며 무제한/장기 soak는 수행하지 않았다.

강제 종료 회귀는 Router build 직후가 아니라 route와 restoration bytes가 실제 파일에 저장된 뒤 종료한다.
저장 전 frame build만 보고 종료한 초기 fixture는 마지막 checkpoint로 복귀했으며, 이를 새 입력의 저장 보장으로 해석하지 않았다.

추가 창의 native 종료 callback을 끝낸 뒤 managed context를 해제한다. 삭제된 창의 Qt queue는
closed 결과로 완료하고, main 창과 무관한 앱 queue를 통해 survivor/reopen을 처리한다.
각 owner의 frame terminal ACK 및 teardown을 검사하며 final diagnostics에서 잔여 Quick GPU 예약과
retiring layer가 0임을 확인했다. 앱 handler는 공통 application lease를 공유한다.

## 렌더링 수치의 범위

600×500/DPR 1의 `reload` 장면을 20회 resize한 한 실행의 진단값이다.
표시 FPS·scanout latency·물리 VRAM·장기 메모리 예산으로 해석하지 않는다.

| Quick 경로 | presented / replayed / failed | peak R/P 예약 bytes | Recording p50 / p95 ms | Fence wait p50 / p95 ms |
| --- | --- | --- | --- | --- |
| Wayland/software Vulkan | 21 / 11 / 0 | 5,529,600 | 0.7392 / 12.7154 | 2.5719 / 8.5005 |
| XWayland/software Vulkan | 18 / 2 / 0 | 5,529,600 | 1.1579 / 21.6248 | 7.6353 / 13.6952 |

양쪽 모두 종료 후 reserved bytes=0, retiring layers=0, full-frame CPU copies=0.
resize 중 오래된 scene은 superseded 처리됐으며 terminal failure는 0이다.
물리 present 간격·전체 process RSS/VRAM·실제 영상 texture·GPU loss·장기 성능 예산은 **notMeasured/notVerified**.

## 재현 명령

저장소 루트에서 실행한다. 도구는 Qt development/QML/QuickControls2/WebEngineQuick와
C++ compiler·CMake·pkg-config·Python 3·고정 .NET SDK가 필요하다. WebEngine 없는 앱은
`DorotiQtWebEngine=false`로 빌드할 수 있다.

```sh
pwsh -NoProfile -File Doroti/eng/doroti.ps1 validate -ValidationSuite LinuxSmoke
python3 Doroti/eng/run-with-timeout.py python3 Doroti/tests/linux_qt_smoke.py --qpa xcb --output temp/testing/linux-qt/reproduce-xcb
python3 Doroti/eng/run-with-timeout.py python3 Doroti/tests/linux_qt_packages.py temp/testing/linux-qt/reproduce-packages
python3 Doroti/eng/run-with-timeout.py dotnet run --project Doroti/tests/Doroti.Tests/Doroti.Tests.csproj
```

`linux_qt_smoke.py --cases multi,desktop,services,navigation,input,resize`로 범위를 선택한다.
기존 output 폴더를 재사용하지 않는다. `DOROTI_QT_URL_PROBE`는 선택적인 loopback URL이며
설정한 경우 실제 기본 브라우저를 연다. 일반 suite는 URL capability만 확인한다.

Widgets 비교는 별도 디렉터리에 CMake `DOROTI_QT_QUICK=OFF`, `DOROTI_QT_GRAPHITE=OFF`,
`DOROTI_QT_WEBENGINE=OFF`로 shim을 만들고 Desktop 없는 runner와 함께 배치한다.
`DOROTI_LINUX_GRAPHITE=0 DOROTI_SAMPLE=qt-widgets DOROTI_QT_VALIDATION_RESIZE_CYCLES=20`로
각 QPA를 실행한다. SDK의 Desktop/Quick 제한을 무시한 조합은 지원하지 않는다.

## 후보와 정리

최종 후보: `Doroti/artifacts/linux/0.3.0-beta.qt.20260929/`.
`candidate.json`에 25개 package와 45개 publish payload의 SHA-256, 기준 revision,
미커밋 source 변경 hash, SDK/Qt, 실제 실행 및 portable 설치 결과를 보존했다.
이는 기존 Windows/Web 후보를 갱신한 것이 아니라 별도의 Linux 로컬 후보다.

```sh
python3 Doroti/eng/install-linux-qt.py install --candidate Doroti/artifacts/linux/0.3.0-beta.qt.20260929 --root /absolute/path/to/doroti-qt --protocol-scheme myapp
/absolute/path/to/doroti-qt/run
python3 Doroti/eng/install-linux-qt.py remove --root /absolute/path/to/doroti-qt
```

installer는 소유 marker와 payload hash를 검사하고 staging 후 `current` symlink를 전환한다.
`run`은 설치 경로의 `userdata`를 XDG_DATA_HOME으로 사용한다. `.desktop` 파일을 생성하지만
사용자의 전역 protocol association을 자동 변경하지 않는다. 실제 배포자는 배포 형식에 맞춰
등록·서명·의존 패키지 설치를 마쳐야 한다. Qt trimming/single-file/NativeAOT는 제공하지 않으며
trimming 요청은 `DOROTIQT001`로 거절되는 것을 검증했다.

원시 로그·캡처·격리 소비 앱·NuGet cache는 `temp/testing/linux-qt/` 아래 이번 실행 소유 폴더에
생성했다. 결과 요약 후 **이번 실행 소유 raw 폴더 삭제를 완료**했으며 최종 후보만 위 artifacts 경로에 보존한다.
초기 Source 실패 폴더 `temp/testing/source/09c5db01618148ff9a286402b36503f4/`도
숨김 staging 검사 수정 후 요약하고 **삭제 완료**했다. 기존 다른 세션 자료는 정리 대상이 아니다.
